# forge — build contract

Single source of truth for everyone building forge. If you need to deviate, note it in
`CONTRACT-CHANGES.md` and keep the old shape working.

forge = a Claude Code plugin + a Python CLI + a local web UI for running projects as trees of
tasks, each task owned end-to-end by one long-lived Claude Code background session ("worker").
It builds on the `superpowers` plugin (brainstorming, writing-plans, test-driven-development,
subagent-driven-development, requesting-code-review, finishing-a-development-branch).

## Constraints

- Python 3.12 **stdlib only** (no pip deps). Node is not required.
- No credentials in the repo. Tokens come from env vars, falling back to `~/.config/forge/env`
  (`KEY=VALUE` lines, chmod 600): `CLICKUP_TOKEN`, `SONAR_TOKEN`. GitHub goes through the `gh` CLI.
- `FORGE_HOME` env var, default `~/agent-projects`. Everything below is relative to it.
- All writes are atomic (write temp + `os.replace`). Timestamps are ISO-8601 UTC (`2026-09-25T12:00:00Z`).
- Every JSON file has `"schema": 1` at top level (lists are wrapped: `{"schema":1,"items":[...]}`).

## Repo layout and ownership

| Path | Owner |
|---|---|
| `forge_lib/` (python package), `bin/forge`, `tests/` | **lib agent** |
| `ui/` | **ui agent** |
| `.claude-plugin/`, `skills/`, `hooks/`, `README.md`, `install.sh`, `docs/` | **plugin agent** |

`bin/forge` is an executable python script that puts the repo root on `sys.path` and calls
`forge_lib.cli.main()`. Skills invoke it as `forge` (install.sh symlinks it to `~/.local/bin/forge`).

## Filesystem layout (`$FORGE_HOME`)

```
<project-slug>/
  project.json                 # [state]    machine state (below)
  project.md                   # [authored] prose: goal, context, decisions
  spec.md tests.md plan.md     # [authored] coordinator-level scoping
  status.md                    # [rendered] task table: state, owner session, gate, open blockers, awaiting-you,
                               #            issues by state, PR health
  decisions.md                 # [rendered] decision log across all tasks (newest first) + "Awaiting your decision"
  tasks/
    <task-dir>/                # task-dir = "<ID>-<slug>", ID = ClickUp custom id if known else "T<n>"
      task.json                # [state]
      spec.md                  # [authored]
      tests.json  tests.md     # [state] / [rendered] tests.md from tests.json + a preserved "## Notes" section
      prs.json    PRs.md       # [state] / [rendered] PRs.md from prs.json (+ task.json for the Problems column)
      issues.json issues.md    # [state] / [rendered] issues.md index; bodies live in issues/<I-n>.md
      issues/I-1.md            # [authored] full issue body, markdown with ```mermaid blocks
      inbox.json               # [state] comments thread (user <-> worker)
      log.md                   # [authored] worker's append-only running log
      status.md                # [rendered] state + recent history, owner session, gate reasons, per-PR problems,
                               #            counts, open issues, children states
      HANDBACK.md              # [rendered] task.json `handback` + gate snapshot, final PR status, tests summary;
                               #            a "Not handed back yet" stub until `forge handback` passes
      tasks/<sub-task-dir>/... # present only when the task was split; same structure recursively
.cache/                        # UI/CLI caches (pr status, clickup), safe to delete
```

**Authored** files are written by people/workers; forge only creates stubs. **State** files are the json
below, mutated only through the CLI. **Rendered** files are regenerated from state and must not be edited
by hand (except the `## Notes` section of a task's `tests.md`).

**Task key** = project slug + task-dirs joined by `/`, omitting the literal `tasks` segments.
E.g. `billing-v2/ENG-101-api/ENG-105-dao` ↔ `$FORGE_HOME/billing-v2/tasks/ENG-101-api/tasks/ENG-105-dao`.
A project key is just the slug.

Rendered `.md` files are regenerated by the CLI on every mutation of their json. For `tests.md`,
anything under a `## Notes` heading is preserved across renders. Any write of a task's json also
re-renders its `PRs.md` and `status.md`, every ancestor's `status.md` and the project `status.md`;
`HANDBACK.md` is written by `forge handback` and `forge render`. `forge render --all` regenerates
every rendered file across FORGE_HOME.

## JSON schemas

### project.json
```json
{"schema":1,"slug":"billing-v2","title":"Billing v2","state":"scoping|active|done",
 "clickup_parent":{"id":"86abc","custom_id":"ENG-100","url":"https://app.clickup.com/t/86abc"} ,
 "repos":[{"path":"/Users/x/src/my-service","github":"example-org/my-service",
           "sonar_project_key":"example-org_my-service","base_branch":"main"}],
 "max_parallel":5,"coordinator_session":{"id":"<uuid>","name":"..."}|null,
 "created":"...","updated":"..."}
```
`clickup_parent` may be null.

### task.json
```json
{"schema":1,"key":"billing-v2/ENG-101-api","title":"...","parent_key":null,
 "depends_on":["billing-v2/ENG-102-schema"],
 "repo":"/abs/path/to/repo","github":"owner/repo","sonar_project_key":"...|null","base_branch":"main",
 "clickup":{"id":"...","custom_id":"ENG-101","url":"..."}|null,
 "session":{"id":"<uuid>","name":"forge-billing-v2-ENG-101-api","worktree":"forge-billing-v2-ENG-101-api"}|null,
 "state":"scoped",
 "state_history":[{"state":"scoped","at":"...","note":""}],
 "gate":{"last_run":"...","passed":false,"reasons":["..."],"consecutive_blocks":0},
 "handback":{"summary":"...","docs":"what docs were updated + paths","at":"...",
             "gate":{"passed":true,"reasons":[],"last_run":"..."}}|null,
 "created":"...","updated":"..."}
```
**States:** `scoped → dispatched → in-progress → (blocked ↔ in-progress) → in-review → handed-back → done`.
`coordinating` = the task was split and its worker now coordinates children. Any → `cancelled`.
Transitions are not strictly enforced except: `handed-back` only via `forge handback` (gate must pass).

Inherited fields: `repo/github/sonar_project_key/base_branch` default from the parent task or the
project's first repo.

### tests.json
```json
{"schema":1,"items":[{"id":"TST-1","name":"rejects negative amount","type":"unit|integration|e2e|manual|ci",
 "command":"./gradlew :gw-shared:test --tests X","expected":"...","status":"pending|red|green|skipped",
 "evidence":"CI run url / output excerpt","skip_reason":"","updated":"..."}]}
```

### prs.json
```json
{"schema":1,"items":[{"repo":"owner/repo","number":123,"url":"...","title":"...","branch":"...",
 "base":"main","stack_index":0,"added":"...",
 "status":{ ...github.pr_status() result..., "sonar": ...sonar.quality_gate() result...,
            "fetched_at":"..."}|null}]}
```
`stack_index` 0 = bottom of the stack.

### issues.json
```json
{"schema":1,"items":[{"id":"I-1","title":"...","severity":"blocker|decision|question|fyi",
 "state":"open|awaiting-user|decided|in-progress|resolved|wontfix",
 "status":"open|resolved|wontfix","file":"issues/I-1.md","artifact_url":null,
 "history":[{"state":"awaiting-user","at":"...","by":"user|worker|coordinator|reviewer","note":"...",
             "comment_id":"C-3|null"}],
 "decision":{"text":"...","by":"user|coordinator","at":"...","comment_id":"C-3|null"}|null,
 "created":"...","updated":"...","resolution":""}]}
```
**Issue states:** `open` (raised, not triaged) → `awaiting-user` (needs the user's answer) → `decided` (user
decided; worker must act) → `in-progress` (worker acting) → `resolved` | `wontfix`. Reopen: closed → `open`.
`forge issues set-state` validates transitions (`issues.TRANSITIONS`); `decide` works from any non-closed
state, `resolve` from any state. `status` is kept in sync (`resolved`/`wontfix`, else `open`) for older
readers. `decision` is the latest one; earlier decisions stay in `history` notes. New issues default to
`awaiting-user` for blocker/decision/question and `open` for fyi. Items without `state` are migrated on load
(state from status/severity, one history entry `{by: reviewer if the task never had a session else worker,
note: "migrated", at: created}`), persisted by the next save or `forge render`.

### inbox.json
```json
{"schema":1,"items":[{"id":"C-1","issue_id":"I-1|null","author":"user|worker|coordinator",
 "body":"...","at":"...","reply_to":"C-0|null",
 "status":"open|acked|resolved","delivered":false}]}
```
Only `author=user` (and `coordinator`) messages carry meaningful `status`/`delivered`.
"Open inbox" = messages authored by user/coordinator with status `open`.

## CLI (`forge`) — all subcommands support `--json` for machine output where it returns data

```
forge home                                     # print FORGE_HOME
forge init-project <slug> --title T [--clickup-parent ID_OR_URL] --repo PATH [--github O/R]
                   [--sonar-key K] [--base-branch main] [--max-parallel 5]
forge new-task <parent-key> <task-dir> --title T [--depends-on K1,K2] [--repo PATH] [--github O/R]
                   [--sonar-key K] [--base-branch B]          # parent-key = project slug or task key
forge list-projects [--json]
forge tree [<project-or-task-key>] [--json]    # nested tree incl. state, session, counts of open issues/inbox, pr summary
forge show <key> [--json]                      # task.json (+ derived paths)
forge path <key>                               # absolute dir
forge set <key> --merge '<json>'               # deep-merge into task.json (or project.json for a slug)
forge set-state <key> <state> [--note N]
forge ready [<project>] [--json]               # scoped tasks whose depends_on are all handed-back/done
forge task-for-session <session-id> [--json]   # reverse lookup (exit 1 if none)

forge dispatch <key> [--message M] [--dry-run] [--force]
forge message <key> <text>
forge sessions [--json]                        # `claude agents --json --all` joined with task keys

forge tests add <key> --name N --type T [--command C] [--expected E]      # prints new id
forge tests set <key> <TST-id> --status S [--evidence E] [--skip-reason R]
forge prs add <key> --url URL [--stack-index N]
forge prs refresh [<key-or-project>] [--all]   # fetch github+sonar status into prs.json
forge issues add <key> --title T --severity S (--body-file F | --body B) [--state S] [--by who]  # prints I-id
forge issues resolve <key> <I-id> --resolution R [--wontfix] [--by who]
forge issues set-state <key> <I-id> <state> [--note N] [--by user|worker|coordinator|reviewer]
forge issues decide <key> <I-id> --decision TEXT [--by user|coordinator] [--comment-id C-n] [--[no-]notify]
                   # -> decided; posts "Decision on I-n: TEXT" (author=by, issue_id set) via agents.send when the
                   #    task has a session, else queued in the inbox. Default notify = no --comment-id given.
forge issues list <key-or-project> [--state S] [--json]
forge issues set-artifact <key> <I-id> <url>
forge inbox add <key> --body B [--issue I-id] [--author user|worker|coordinator] [--reply-to C-id]
forge inbox list <key> [--open] [--json]
forge inbox ack <key> <C-id>
forge inbox resolve <key> <C-id> [--reply B]   # optional reply is stored as a worker message
forge inbox pending [--json]                   # all undelivered open user msgs across FORGE_HOME
forge inbox mark-delivered <key> <C-id>
forge gate <key> [--json]                      # run checks, update task.gate, exit 0 pass / 1 fail
forge handback <key> --summary S --docs D      # runs gate; on pass sets state handed-back
forge hook stop                                # Stop hook entry (reads hook JSON on stdin)
forge hook session-start                       # SessionStart hook entry (reads hook JSON on stdin)
forge render (<key> | --all)                   # regenerate rendered md (task/project, or all of FORGE_HOME)
forge adopt-scan --clickup-parent ID [--repo PATH] [--github O/R] [--json]
forge ui [--port 7777]                         # runs ui/server.py
```

### dispatch semantics
- Name = `forge-` + key with `/` → `-`, worktree name = same as name. `claude --bg` ignores
  `--session-id`, so after launch forge records the real `sessionId` (and short `bg_id`) of the newest
  agent with that name from `claude agents --json --all`. Resume also passes `-n <name>` and re-resolves
  (a resume gets a new session id). Active = listed by `claude agents --json` and not failed/stopped;
  `done`+`idle` is ACTIVE (process alive; resuming it would fork).
- First dispatch (no `task.session`): run, with `cwd=task.repo`:
  `claude --bg -n <name> -w <worktree> "<worker prompt>"`.
  Worker prompt: `You are the forge worker for task <key>. Task folder: <abs path>. Invoke the forge:work skill and follow it.` + `--message`.
- Refuse (exit 1) if depends_on not all `handed-back|done`, or the project already has
  `max_parallel` tasks in `dispatched|in-progress`, unless `--force`.
- Re-dispatch (session exists): if the session is currently active per `claude agents --json`,
  do NOT start anything: write the message to the inbox (author coordinator) and print
  `ACTIVE: use SendMessage to <name>` (exit 3). Otherwise
  `claude --bg --resume <uuid> "<message or 'Resume task <key>; check inbox.'>"` with `cwd=task.repo`.
- Sets state `dispatched`. `--dry-run` prints the command only.
- `forge message` = same as re-dispatch with a mandatory message.

### gate checks (all must pass)
1. `tests.json` has ≥1 item and every item is `green` or `skipped` with a `skip_reason`.
2. `prs.json` has ≥1 PR; after a fresh refresh each PR: checks rollup `SUCCESS`
   (no FAILURE/ERROR/PENDING), zero unresolved review threads, sonar status `OK` when
   `sonar_project_key` is set (sonar `NONE` = not analysed yet → fail with reason "sonar pending").
   Drafts are allowed. Also fails on: `mergeable=CONFLICTING`; any `task.required_checks` entry
   (substring of a check name) that never ran (skipped counts as not run - catches draft-gated
   builds); a stacked PR whose `base_oid` differs from the PR below's `head_oid` (stale stack).
3. No open inbox messages from user/coordinator.
4. No child tasks (if any) outside `handed-back|done|cancelled`.
5. No issue in state `decided` or `in-progress` (a decision not yet acted on - resolve it).
`forge handback` additionally requires non-empty `--summary` and `--docs`.

### hooks
- `forge hook stop`: stdin is Claude hook JSON (`session_id`, `stop_hook_active`, `cwd`...).
  Map session → task (exit 0 silently if none). Block (print
  `{"decision":"block","reason":"..."}` on stdout, exit 0) when:
  (a) there are open inbox messages not yet acked — reason lists them; or
  (b) task state is `in-review` and gate fails — reason lists gate reasons, tell the worker to
      keep fixing/monitoring CI, or set state `blocked` with a note and write an issue if it needs the user.
  Never block more than 5 consecutive times (`gate.consecutive_blocks`); on the 6th, allow,
  set state `blocked` with note. Reset the counter when not blocking.
- `forge hook session-start`: stdin hook JSON. If the session maps to a task, print (stdout,
  becomes context) a compact briefing: key, state, task folder path, the spec.md head (≤60 lines),
  last 30 lines of log.md, open inbox messages, open issues, PR summary, gate reasons.

## Integrations (`forge_lib/integrations/`) — signatures the UI also imports

```python
# github.py (uses `gh api graphql`)
def pr_status(repo: str, number: int) -> dict
# -> {"url","title","state":"OPEN|MERGED|CLOSED","is_draft":bool,"base":str,"head":str,
#     "review_decision":str|None,
#     "checks":{"state":"SUCCESS|FAILURE|PENDING|NONE","total":int,"failing":[{"name","url"}],"pending":[{"name"}]},
#     "threads":{"total":int,"resolved":int,"unresolved":int,
#                "items":[{"id","path","line","is_resolved","is_outdated",
#                          "comments":[{"author","body","at","url"}]}]},
#     "comments_count":int,"updated_at":str}
def parse_pr_url(url: str) -> tuple[str, int]   # ("owner/repo", 123)

# sonar.py (SonarCloud, basic auth token)
def quality_gate(project_key: str, pr_number: int) -> dict
# -> {"status":"OK|ERROR|WARN|NONE","conditions":[{"metric","status","actual","threshold"}],
#     "url":"https://sonarcloud.io/summary/new_code?id=<key>&pullRequest=<n>"}

# clickup.py
def get_task(task_id: str, include_subtasks: bool = True) -> dict   # raw ClickUp task json
def create_task(list_id: str, name: str, description: str = "", parent: str | None = None) -> dict
def task_summary(task: dict) -> dict  # {"id","custom_id","name","status","url","assignees":[names],"subtasks":[summary...]}
```
All integration functions raise `forge_lib.errors.IntegrationError` on failure (message includes
what failed, never the token).

## UI (`ui/server.py`, `python3 ui/server.py --port 7777`, bind 127.0.0.1)
stdlib `ThreadingHTTPServer`; static SPA in `ui/static/` (vanilla JS, `marked` + `mermaid` from
cdn.jsdelivr.net). Background thread refreshes PR status every 120s and ClickUp every 300s.

API:
```
GET  /api/projects                      -> [project + tree counts]
GET  /api/tree?key=K                    -> tree node
GET  /api/project?slug=S                -> {project, tree, clickup: summary|null}
GET  /api/task?key=K                    -> {task, tests, prs, issues, inbox, spec_md, log_tail}
GET  /api/prs?project=S (optional)      -> [{task_key, ...prs item}]
GET  /api/issues?project=S&status=open&state=S|active|all -> [{task_key, ...issue incl. state/history/decision}]
GET  /api/issue?key=K&id=I-1            -> {issue, next_states, body_md, thread:[inbox msgs for issue]}
POST /api/issue/decide {key,id,decision} -> {issue, delivery:{mode,delivered,detail,message}} (by=user;
                                           --no-nudge only queues the message)
POST /api/issue/state {key,id,state,note?} -> issue (by=user; 409 on an invalid transition)
POST /api/inbox  {key, body, issue_id?} -> created msg (author user); then best-effort nudge:
                                           if session inactive -> forge dispatch-style resume; else leave
                                           delivered=false for the coordinator relay
POST /api/refresh {key?}                -> triggers prs.refresh
GET  /api/fs/tree?path=REL              -> {name, rel, type:"dir", size:null, mtime, kind, role:project|task|dir,
                                            children:[{name, rel, type:dir|file, size, mtime, kind, ...}]}
GET  /api/fs/file?path=REL[&meta=1]     -> {rel, size, mtime, kind, source, content}; meta=1 omits content
```
`kind` = `state` (*.json) | `rendered` | `authored` | `other`; `source` names the json a rendered file comes
from. File reads are read-only and confined to FORGE_HOME: absolute paths, `..`, dotfiles, `.cache`,
`__pycache__` and symlinks resolving outside FORGE_HOME → 400; missing → 404; > 2 MB → 413; non-UTF-8 → 415.
`/api/fs/*` also refuses (403) a non-local `Origin` or `Host` header.
Views: Projects list · Project dashboard (task tree w/ states, ClickUp parent + subtasks status,
dependency list, live sessions + `claude attach <id>` copy button) · PRs (grouped by project→task→stack;
CI, sonar, threads resolved/unresolved, draft, links) · Issues (list with project/state/severity filters,
state default "not closed", "N awaiting you" pill → issue page: state badge, decision callout, timeline,
Record decision / Change state / Reopen, markdown+mermaid body, artifact link if set, comment thread + box) · Files (`#/files/<rel>`: tree of
FORGE_HOME + viewer for md (rendered, relative links stay in the view) / json (collapsible) / raw).
